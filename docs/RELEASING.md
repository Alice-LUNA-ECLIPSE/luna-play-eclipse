# Публикация релиза Luna Play Eclipse

Эта инструкция описывает ручной выпуск Windows-версии через GitHub Releases. Сборка настроена на NSIS; `npm run dist` создаёт установщик в `dist/`.

## Перед выпуском

1. Убедитесь, что изменения проверены и нужные файлы закоммичены. Не выпускайте релиз из случайного набора незакоммиченных изменений.
2. Проверьте `git status --short`. В репозитории должны быть доступны `package-lock.json` и `build/icon.ico`: первый фиксирует версии зависимостей, второй указан в настройках сборки.
3. Выберите новую версию по SemVer:
   - `patch` — исправления, например `3.2.5` → `3.2.6`;
   - `minor` — новые совместимые функции, например `3.2.5` → `3.3.0`;
   - `major` — несовместимые изменения, например `3.2.5` → `4.0.0`.
4. Обновите версию командой `npm version patch` (или `minor` / `major`). Она обновит `package.json` и `package-lock.json`, создаст commit и Git-тег `vX.Y.Z`. Перед запуском проверьте, что нет несохранённых изменений: npm может отказаться создавать версионный commit при грязном рабочем дереве.
5. Соберите и запустите приложение на Windows:

   ```powershell
   npm ci
   npm start
   npm run dist
   ```

6. Проверьте установщик из `dist/`: установку и удаление, запуск, открытие нескольких файлов, видео и аудио, субтитры, настройки и полноэкранный режим.
7. Проверьте имя и версию результата, затем посчитайте SHA-256:

   ```powershell
   Get-FileHash ".\dist\Luna Play Engine Setup X.Y.Z.exe" -Algorithm SHA256
   ```

## Отправка тега

После проверки отправьте commit и созданный тег в GitHub:

```bash
git push origin main --follow-tags
```

Если рабочая ветка называется иначе, замените `main` её именем. Команда отправляет все локальные commits текущей ветки, поэтому перед запуском просмотрите `git status` и `git log`.

## Создание GitHub Release

1. Откройте [Releases](https://github.com/Alice-LUNA-ECLIPSE/luna-play-eclipse/releases) и выберите **Draft a new release**.
2. Выберите отправленный тег `vX.Y.Z`.
3. Укажите заголовок `Luna Play Eclipse vX.Y.Z`.
4. Опишите новые возможности, исправления, известные ограничения и при необходимости шаги обновления. GitHub умеет сгенерировать черновые заметки, но их стоит проверить перед публикацией.
5. Прикрепите только установщик `Luna Play Engine Setup X.Y.Z.exe`. Не загружайте `.vs`, `node_modules`, папку `win-unpacked`, логи и временные файлы. `latest.yml` и `.blockmap` используются механизмом автообновления; в проекте сейчас нет `electron-updater`, поэтому эти файлы сами по себе автообновления не включают.
6. Сверьте имя файла и версию, добавьте SHA-256 в заметки и опубликуйте релиз. Для тестовой сборки включите **Set as a pre-release**.
7. После публикации откройте страницу релиза как обычный посетитель и проверьте скачивание установщика.

## Рекомендации перед публичным запуском

- Не используйте `"electron": "latest"` для стабильных выпусков: зафиксируйте проверенную версию Electron и храните актуальный `package-lock.json` в Git.
- Текущий локальный установщик занимает около 96 MiB. Не обещайте маленький размер загрузки или низкое потребление памяти без измерений на целевом компьютере.
- Подпишите Windows-установщик сертификатом, если хотите уменьшить предупреждения SmartScreen. Без подписи Windows может показывать предупреждение о неизвестном издателе.
- Добавьте актуальные скриншоты главного окна и настроек в `docs/screenshots/`.
- Автоматизацию через GitHub Actions лучше добавить после успешного ручного выпуска: сборка по тегу `v*`, проверка версии, сборка на Windows и прикрепление установщика к черновику релиза.
